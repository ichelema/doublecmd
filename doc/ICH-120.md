# ICH-120: file-source integration

## Reference and scope

- Issue: <https://linear.app/ichelema/issue/ICH-120>
- Original repository: <https://github.com/doublecmd/doublecmd>
- Fork: <https://github.com/sphynx79/doublecmd>
- Fork baseline: `9ec6a09878da52034240750cd577cc2febcd0a31`.
- Upstream reviewed through `69a686c3c` (2026-09-28), including changes after
  the issue's original `46cf2dbb4..12fe40c33` range.

This is a selective port, not an upstream merge. Tree File View, its expanded
directory watches, and the Qt6/Wayland fixes remain in place.

## Upstream changes

- **Typed existence checks:** `c1b5a8671`, `0e112e686`, `c237e1639`.
  Distinguish files, directories, missing entries and unsupported queries;
  adapt existing callers.
- **Real-path mapping:** `5f88a9dd6`, `1578e7573`, `ef2a5c5ab`.
  Resolve mapped paths before filesystem checks, directory creation and
  navigation.
- **WFX existence and refresh:** `f494177ff`, `297dc0594`, `edb1139f6`,
  `a67423a39`. Validate navigation, recognize empty directories and refresh
  after directory creation.
- **WFX download timestamps:** `06db49f68`.
  Preserve local timestamps even when the plugin lacks `FsSetTime`.
- **Stash existence and refresh:** `0d029c593`, `18ec12f75`.
  Query entries without triggering a continuous refresh cycle.
- **Synchronization capabilities:** `bf0ce76b0`, `da5e4ac76`.
  Advertise capabilities and reject unsupported source pairs without
  importing the SyncDirs refactor.
- **iCloud operation checks:** `bf142322a`.
  Allow capability consultations without a concrete file selection.
- **macOS FSEvents:** `a64f063c2`, `1f208199a`.
  Do not hold the watcher lock while updating or closing the event stream.

### Adaptations to this fork

- WCX keeps its existing locked archive list; no new archive index is imported.
- Unsupported existence queries remain permissive through the Boolean helpers.
  Implementations supporting the query reject empty option sets.
- Stash callbacks tolerate `setListener(nil)`. Internal metadata refreshes do
  not notify listeners; removing an absent path must not remove another entry.
- Stash retains its path list rather than sharing cached `TFile` objects.
  Lookups return fresh, caller-owned metadata, avoiding stale entries and
  ownership races after releasing the backend lock.
- Mapped mount points are recognized with and without a trailing separator.
- GIO must not report an unknown/missing entry as present when both file and
  directory types are requested.

### Deliberately deferred dependencies

- `997711865`, preserving mounted iCloud directory names when copying to
  MultiArchive/7z, depends on archive subdirectory support such as `5a3280c58`.
  The baseline still aborts a non-root target without `%R` in
  `TMultiArchiveCopyInOperation.Initialize`. Keep the existing iCloud workaround
  until that archive work is integrated under ICH-118.
- `c210981df` and later directory-attribute helpers have no necessary caller in
  this port. Integrate them with their synchronization/archive consumers, not
  as unused helpers.
- The SyncDirs model/view refactor and empty-directory action propagation
  belong to ICH-119.

## Validation

The Qt6 release build and automated regression program passed on Linux
x86-64 with Free Pascal 3.2.2, Lazarus 4.8 and qt6pas 6.2.10.
The build uses `Copy` for the Stash path slice: Free Pascal 3.2.2 rejects
calling `Substring` directly on the result of `ExcludeTrailingPathDelimiter`.

Build the components and application with the project's existing commands:

```sh
lcl=qt6 ./build.sh components
lcl=qt6 ./build.sh doublecmd
```

### Automated regression program

`tests/filesource_regression.lpr` exercises the real filesystem and Stash
backend, unsupported-query compatibility, mapped paths, mount roots with and
without a separator, failed navigation, object ownership and notifications.
It uses disposable files, not the user's Double Commander configuration.

On Linux, from the worktree root, after installing the build prerequisites:

```sh
lcl=qt6 ./build.sh components
lazbuild --ws=qt6 tests/filesource_regression.lpi
mkdir -p "$HOME/.pi/agent/tmp"
scratch=$(mktemp -d "$HOME/.pi/agent/tmp/ich120-test.XXXXXX")
QT_QPA_PLATFORM=offscreen \
  ./units/x86_64-linux-tests/filesource_regression "$scratch"
rmdir "$scratch"
```

Use the corresponding CPU/OS output directory on another Linux target.
The application units pulled in by the test do not support Lazarus `nogui`;
Qt6's `offscreen` backend runs these checks without opening windows.
The program completed with exit code 0 and
`PASS: filesystem and stash regression checks`.
The native-platform and interactive scenarios below remain manual checks,
not claims of automated coverage.

### Manual regression checklist

Use disposable data, compare contents and timestamps, and exercise operations
in both Columns View and Tree File View where supported.

1. **WFX:** browse the root, a nonempty directory and an empty directory.
   Reject missing directories and attempts to enter a file. Create a directory
   and check refresh in both panels. Copy nested empty directories in and out.
   Download with a plugin lacking `FsSetTime`, with timestamp preservation both
   enabled and disabled.
2. **Stash:** add files and directories, refresh repeatedly and navigate back
   to the root. Reject arbitrary paths. Rename/delete an underlying file and
   check the list. Close Stash and modify the backend without a listener.
3. **GIO and Windows Shell:** distinguish files, directories and missing
   entries. Exercise create/copy/move/rename/delete and refresh. Verify that
   synchronization is offered only for supported source pairs.
4. **WCX:** enter the root and existing nested directories, reject missing
   directories, and check file-versus-directory existence. Open, extract and
   refresh an existing archive.
5. **Mounted/iCloud on macOS:** check virtual-to-real paths, including mount
   points without a trailing separator. Reject missing directories without
   changing the current working directory. Check ordinary file operations and
   the existing mounted-directory archive behavior.
6. **FSEvents on macOS:** repeatedly add/remove directory watches and close
   views, including watches on slow SMB mounts. Confirm responsive UI,
   continued refresh and clean shutdown.
7. **Tree File View and Qt6/Wayland:** expand nested directories, enter an
   expanded child, then create/rename/delete files externally and verify
   refresh preserves expansion. Exercise copy, move and drag-and-drop; open
   Options and check that the existing tooltip workaround remains effective.

Windows Shell and macOS/iCloud/FSEvents require their native platforms.
Tree expansion remains limited to filesystem sources; this issue does not
add virtual-source expansion.
