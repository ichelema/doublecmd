# ICH-125: localization updates

## Scope

- Issue: <https://linear.app/ichelema/issue/ICH-125>
- Upstream: <https://github.com/doublecmd/doublecmd>
- Fork baseline: `3fd0ea4a8`.
- Upstream reviewed through `2b53e2e1a`, including language commits after
  the original `46cf2dbb4..12fe40c33` review range (`282b0dda2` Swedish,
  `c46ce4e92` Hungarian, `52d69713d`/`f3cbe6b4e` Chinese, `69a686c3c`
  Russian, `24f8f408c` Korean).

Selective integration of `language/` only. Tree File View, async drag/drop
and Qt6/Wayland fixes are untouched.

## Selected upstream changes

- All `language/doublecmd.*.po` and `language/doublecmd.pot` as of upstream
  `2b53e2e1a`: Russian, Simplified/Traditional Chinese, Slovak, Hungarian,
  Korean updates, the new Swedish catalog (`doublecmd.sv.po`,
  `lcl/lclstrconsts.sv.po`) and the shared template entries added by
  `bf2a313f9` (sync "empty directories", "?" filter button).
- `987584210` + `565dcb4c7`: `foptionskeyboard.lfm/.lrj` hint uses `&&`
  (macOS accelerator escape). Taken because every upstream catalog already
  carries the `&&` msgid; without the source fix the fork would have
  regenerated the old `&` entry and dropped all translations of that hint.

### Deliberately unchanged

- Upstream features not integrated in the fork are not kept as orphan
  entries: `tfrmoptionscolors.lbldirselection.caption` (`b6a9d9914`),
  `tfrmoptionstabs.cbtabsunavailablemarker.caption`,
  `tfrmsyncdirsperformdlg.chkverify.caption` (`e7236ed9e`) are removed by
  regeneration from the fork sources. They come back automatically when
  those features are ported.
- `doublecmd.fr.po` header is malformed upstream (translator comments before
  the header, no charset). Pre-existing, `msgfmt` warns, runtime unaffected.

## Fork strings

`src/fmain.lrj` never listed `actTreeFileView` (the `.lrj` is only rewritten
by the Lazarus IDE on form save), so the template could not carry the Tree
File View strings and the Italian entry in `doublecmd.it.po` was hand-added.
The two `.lrj` entries were added with the IDE's hash algorithm
(`TTranslateStrings.CalcHash`) in LFM streaming order; the Italian
translation (`Albero` / `Vista ad albero`) is preserved by the merge and the
other 30 catalogs now carry the untranslated entries.

## Regeneration process

The IDE regenerates `doublecmd.pot` and merges all `.po` files on build
(`EnableI18N` in `doublecmd.lpi`). `lazbuild` does not. The headless
equivalent is `tools/updatelang.lpr`, which uses the same `TPOFile` code
(`lazutils/translations.pas`), restricts `.rsj` input to project units and
applies the `.lpi` `ExcludedOriginals`:

```sh
lazbuild -B src/doublecmd.lpi --bm=release --widgetset=qt6   # fresh .rsj
fpc -FE/tmp -FU/tmp -Fu/usr/lib/lazarus/components/lazutils/lib/x86_64-linux tools/updatelang.lpr
/tmp/updatelang language/doublecmd.pot $(git ls-files 'src/*.lrj') \
  units/x86_64-linux-qt6/{fsyncdirsdlg,uadministrator,uexifreader,ulng,umaincommands}.rsj
```

Checked against upstream: regenerating from the fork sources with upstream
catalogs as input yields exactly the expected template delta (+2 Tree
entries, −3 non-integrated entries) and no other difference. Catalogs saved
by gettext tools upstream (Korean) are re-wrapped to one-line msgid/msgstr,
which is what the next upstream IDE build does too.

`lazbuild --bm=release` without `-B` hit FPC `Internal error 200510011` in
`fmain.pas` on top of the stale unit cache; a full rebuild compiles cleanly.

## Validation

Environment: Linux x86-64, FPC 3.2.2, Lazarus 4.8, Qt 6.11.2, Hyprland.

- `msgfmt -c` on `doublecmd.pot`, all 31 `doublecmd.*.po` and `lcl/*.po`:
  no errors (only the pre-existing `fr.po` header warnings).
- `tests/language_regression.lpr`: every catalog has exactly the template's
  identifiers, Tree entries present everywhere and Italian in `it.po`, the
  three non-integrated identifiers absent. Negative check against the
  upstream template fails as expected (36 failures).
- Qt6 release build after the LFM change.
- Double Commander launched offscreen with each of the 31 catalogs in a
  fresh config dir: `Loading lng file` logged for every one, no exception
  except Korean (below).
- Native Wayland run in Italian: menus, toolbar, drive bars, status bar and
  function-key bar translated; language persisted in `doublecmd.xml` and
  reloaded on restart. The Show menu could not be opened by synthetic input
  (`wtype`) under Qt/Wayland, so the Tree entry was verified through the
  catalog check rather than a menu screenshot.

### Known pre-existing issue

`doublecmd.ko.po` raises `EStringListError: String list does not allow
duplicates` in a SynEdit highlighter constructor at startup. Reproduced with
the fork baseline `ko.po` as well, so it is independent of this integration.
Likely cause, not yet confirmed: `TPOFile.Translate` falls back to matching
by original text and two highlighter attribute captions (used as
`StoredName`) receive the same Korean translation. Tracked separately.
