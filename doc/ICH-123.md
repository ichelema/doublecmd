# ICH-123: Linux build and packaging updates

## Scope

- Issue: <https://linear.app/ichelema/issue/ICH-123>
- Upstream: <https://github.com/doublecmd/doublecmd>
- Fork baseline: `e5f0460ca`.
- Upstream reviewed through `2f5ef9a0a` (2026-10-03).

Build and packaging files only. The application sources are not touched;
the production installation in `/opt/doublecmd` is not changed.

## Selected upstream changes

The fork had no local changes under `install/` or `.github/`, so the three
files are taken as they are upstream:

- `install/linux/install.sh` (`06c9f1a74`, `afc30494c`, `4bf7361a1`):
  `USR_SHARE` variable for the `--install-prefix` layout; when `zip` is
  available, `pixmaps/dctheme` is packaged as `index.theme` plus a stored
  `icon-theme.zip` (`zip -0 -qrDX … -x *theme*`), otherwise the loose tree
  with `icon-theme.cache` as before. The fork's ZIP theme loader from ICH-121
  reads exactly this layout.
- `.github/scripts/create_snapshot.lnx` (`819dc0ac4`, `50d7463bd`): builds
  GTK3 and Qt6 Linux snapshots, links `libQt6Pas.so.6` from the external
  libraries for the Qt6 link step.
- `.github/workflows/snapshots.yml` (`7ff961ece`, `2f5ef9a0a`): macOS 15
  runner with cached FPC 3.2.4-rc2, Lazarus `fixes_5`, `zip` among the Linux
  dependencies.

### Deliberately unchanged

- GTK3 `XInitThreads` guard (`76d6e503b` vs. the fork's unconditional call):
  ICH-121 decided to initialize Xlib locking without guessing the backend
  from `XDG_SESSION_TYPE`/`GDK_BACKEND`. Kept.
- `ddef36eff` (XDG icon lookup) and `a53c8e753` (Lazarus 5.99) belong to the
  UI/theme workstream and were handled or deferred there.
- Production deployment. `/opt/doublecmd` is a self-contained directory
  (binary, `.zdli`, `language/`, `pixmaps/dctheme` as loose files, plugins,
  bundled `libunrar.so` and `libQt6Pas.so.6`) with the configuration in
  `~/.config/doublecmd`, reached through the `/usr/local/bin/doublecmd`
  symlink. It matches neither `install.sh` mode: `--portable-prefix` would
  add `settings/doublecmd.inf` and move the configuration into the program
  directory. Updating it stays a manual copy of the built artifacts.

## Automated checks

Clean build from a fresh worktree of this branch (Linux x86-64, FPC 3.2.2,
Lazarus 4.8, Qt 6.11.2, system `qt6pas` 6.2.10):

```sh
git worktree add --detach "$HOME/.claude/tmp/ich123/wt" HEAD
cd "$HOME/.claude/tmp/ich123/wt"
lcl=qt6 ./build.sh release          # components, plugins, doublecmd, .zdli
cp -p /opt/doublecmd/libunrar.so .  # bundled library expected by install.sh
install/linux/install.sh --install-prefix="$HOME/.claude/tmp/ich123/stage"
install/linux/install.sh --portable-prefix="$HOME/.claude/tmp/ich123/portable"
```

- `build.sh release` compiled 856 units in 22 s and produced `doublecmd`,
  `doublecmd.zdli`, all WCX/WDX/WFX/WLX/DSX plugins. The two
  `dmhigh.json`/`doublecmd.svgz` resource notes are pre-existing.
- `install.sh` needs at least one `*.so*` in the source root in prefix mode
  (`set -e` + `install *.so*`); snapshots copy the external libraries first.
- Staged prefix: `usr/bin/doublecmd → ../lib64/doublecmd/doublecmd`,
  `usr/lib64/doublecmd/{doublecmd,doublecmd.zdli,plugins/…,default,doc,
  highlighters,language,pixmaps}` with `language`/`pixmaps`/`highlighters`
  symlinked to `usr/share/doublecmd`, 33 `doublecmd.*.po` + 35 LCL catalogs,
  `pixmaps/dctheme/{index.theme,icon-theme.zip}` (1190 stored entries),
  `doublecmd.desktop`, `doublecmd.png`, hicolor SVG link resolving inside the
  prefix, man page, polkit policy, `usr/lib64/libunrar.so`.
- Portable prefix: `doublecmd/` with `settings/`, `doublecmd.sh`, loose
  `pixmaps/dctheme`, libraries and plugins.
- Staged binary launched offscreen with an isolated `--config-dir` and
  `strace -e open,openat`: opens `icon-theme.zip` and `index.theme`,
  `doublecmd.it.po`/`lclstrconsts.it.po`, highlighters, `pinyin.tbl` and
  the plugins from the staging prefix only; no exception in the debug log.
- Staged binary launched natively under Hyprland/Wayland: Italian UI, DC
  theme icons from the ZIP, symlink overlays on the staged directories,
  Columns view listing both `/opt/doublecmd` and the staged directory.
- `lcl=gtk2 ./build.sh doublecmd` in the same worktree builds; the GTK2
  binary starts through Xwayland (`DISPLAY=:1`) without exceptions or GTK
  criticals in 8 s.
- Uninstall: `install.sh` writes only below `DC_INSTALL_DIR`,
  `DC_INSTALL_PREFIX` and `USR_SHARE`; removing the prefix removes the 178
  installed files/links. `~/.config/doublecmd` was not modified by any step.

## Interactive regression cases

From the staged prefix with an isolated `--config-dir` on Hyprland/Wayland:

1. HiDPI scaling of the main window, dialogs and the viewer.
2. Tree File View: expand, refresh, switch views, drag-and-drop of disposable
   files between panels.
3. Open the Options dialog and a WLX viewer; no input-grab freeze.
4. Icons: DC theme (`Icons/Theme = dctheme`) renders toolbar, drive and file
   icons from `icon-theme.zip`; switching to the system theme still works.
5. If a GTK build is used: startup and icon rendering on X11/Xwayland.
