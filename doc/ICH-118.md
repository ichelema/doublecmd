# ICH-118: archive updates (7z, ZIP, WCX, MultiArchive)

## Scope

- Issue: <https://linear.app/ichelema/issue/ICH-118>
- Upstream: <https://github.com/doublecmd/doublecmd>
- Fork baseline: `dfa69c31a`.
- Upstream reviewed through `2b53e2e1a`, including the archive commits after
  the original `46cf2dbb4..12fe40c33` range.

Selective integration of the archive layer only. Tree File View, async
drag/drop and Qt6/Wayland fixes are untouched; the archive file sources had
no fork-specific code besides the ICH-119 `FileSystemEntryExists` shim for
WCX, which upstream supersedes.

### Fixed on top of upstream

- **ZIP `FollowLinks=1` archived the host root.** In
  `TAbSymlinkFollowProcessor.onAddItem` upstream resolves every nested
  directory with `mbReadAllLinks()`, which returns `''` for a regular
  directory; `addDirectory('')` then walks `/`. Reproduced under gdb (frames
  in `/bin`, `/usr/bin/vendor_perl`, …). Now only real symlinks are resolved,
  the real paths being expanded are tracked on a stack so a link to an
  ancestor (`loop -> ..`) is added as an empty directory instead of recursing
  forever, and `addDirectory` no longer recurses itself (`onAddItem` does,
  once, with the guard).
- **Archive root in `FileSystemEntryExists`.** Upstream looks the root up in
  the entry index and reports `notExist`, which broke the ICH-119 Synchronize
  Directories WCX scenario. Root paths with or without the delimiter report
  `exists` for `needDir`, both in WCX and MultiArchive.

### Deliberately unchanged

- `uFileSourceUtil`: `CreateDirectoryFromFile`/`CreateDirectory` helpers
  (`5f35bdeec`, `fa31e2574`, `a39afbbfb`) are only used by upstream's
  synchronization; ICH-119 chose checked operations instead. Upstream's
  `isCompatibleFileSourceForCopyOperation` compares `fs1` with itself; the
  fork keeps `fs1.Equals(fs2)`. `GetCopyOperationType` stays.
- macOS iCloud and Windows Recycle Bin changes, `DARWIN` creation-time
  properties, cosmetic `self.GetRealPath` edits.
- CPIO (`37b69e803`, `6072f4fb3`) and UnRAR (`d7225e412`) plugin fixes: WCX
  plugins outside the 7z/ZIP/MultiArchive scope; straightforward to take in a
  follow-up.
- Renaming inside archives: neither file source offers `fsoSetFileProperty`,
  so "rename within" is not an archive operation in Double Commander.

QT_QPA_PLATFORM=offscreen \
  ./units/x86_64-linux-archive-tests/archive_regression --config-dir="$scratch" --follow-links

`tests/archive_regression.lpr` uses the real `zip.wcx`
(`ICH118_ZIP_PLUGIN` overrides `plugins/wcx/zip/zip.wcx`) and the shipped
`7Z` MultiArc addon with the `7z` executable, in an isolated configuration:

- create a ZIP and a 7z by copy-in to the root: file, nested tree, empty
  directory; `FileSystemEntryExists` for files, directories, root (with and
  without delimiter) and missing entries; `SetCurrentWorkingDirectory`;
- copy-in to a new subdirectory `sub/deeper/` (7z: hard-link working tree);
  listings of root and subdirectory;
- copy-out from root and subdirectory: contents, empty directory,
  modification times (2 s tolerance);
- archive-to-archive in both directions through `TTempFileSystemFileSource`
  exactly as `TfrmMain.CopyFiles` does, into a new subdirectory, verified by
  listing and copy-out;
- delete from the archive and listing afterwards; external `7z a` picked up
  by the next list operation;
- ZIP symbolic links to a file, to a directory and to an ancestor (`..`):
  `FollowLinks=0` stores and extracts them as links; `--follow-links` writes
  `zip.ini` with `FollowLinks=1` before the plugin loads and checks the
  targets are stored, the recursive link stops, and extraction yields real
  files.

Results on Linux x86-64, FPC 3.2.2, Lazarus 4.8, Qt 6.11.2, 7-Zip 26.03:
both modes pass. Against the unmodified `master` sources the same program
fails the 7z root/subdirectory copy, archive-to-archive and refresh checks;
with upstream's plugin before the fix the `--follow-links` run hangs while
walking `/`.

Existing suites: `filesource_regression`, `functional_regression` and
`syncdirs_regression` (with `ICH119_ZIP_PLUGIN`/`ICH119_ZIP_ARCHIVE`, 16/16)
pass. `fileview_saved_path_regression` fails with "missing path has parent
entry" on this machine both on `master` and on this branch; pre-existing and
unrelated.

The release build was started natively under Wayland with the test archives'
directory in both panels; it starts and lists them. Entering the archives
was not driven by synthetic input.

## Interactive regression cases

Use disposable archives and an isolated `--config-dir`, in Columns and Tree
File View:

1. Create, open, copy into, extract from and delete from a ZIP and a 7z.
2. Copy files and nested directories into a new archive subdirectory
   (`F5` to `archive/sub/deeper/`); the view must refresh immediately.
3. Copy between two archives (ZIP → 7z and back) and compare names, paths,
   contents and timestamps.
4. Empty directories survive copy-in and copy-out.
5. ZIP: pack a file link, a directory link and a link to an ancestor with
   `FollowLinks` off and on (Configure in the plugin options); the second run
   must finish and must not contain anything outside the selection.
6. Repeat copy, move and drag-and-drop from Columns View and Tree File View
   into an archive subdirectory.
