## ZIP format and safety

`index.theme` stays outside `icon-theme.zip`. Archive entries use the relative
paths declared by the theme. The fast in-memory loader supports single-disk,
stored ZIP entries, including UTF-8 names; it does not extract files.

Compressed/encrypted entries, data descriptors, ZIP64 and archive comments
are not supported. An invalid archive is rejected and the existing loose-file
lookup remains available. For example, from a theme directory:

```sh
zip -0 -qrDX icon-theme.zip */
```

Pass only directories actually declared by that theme.

The port additionally:

- Checks directory/header/data bounds and matching stored-entry sizes before
  exposing any archive memory to an image decoder.
- Rejects empty filenames and mismatched local/central headers.
- Matches exact icon directories and skips unrelated files rather than
  stopping at the first README or unsupported extension.
- Frees the archive and replaced icon-cache lists with their owning theme.
- Constructs all ZIP directory lists before publishing them, retaining loose
  lookup if archive loading fails.

Changing the configured icon theme still requires an application restart,
as in the existing Options dialog. No live-reload feature was introduced.

## Additional review corrections

- If a selected theme has disappeared, load its configured defaults through
  the same parent-theme factory. This also preserves ZIP-backed defaults
  and system-theme fallback to `hicolor`.
- MIME cache version 3 includes the ordered source directories and the
  modification times/sizes of `globs`, `icons` and `generic-icons`.
  Removing or reordering XDG directories invalidates the cache even if
  the maximum `globs` timestamp is unchanged. Versions 1 and 2 are rebuilt.
- Initialize Xlib threading without guessing GTK's backend from environment
  variables. `XInitThreads` initializes locking; it does not open a display
  or select X11 instead of Wayland. A runtime probe of the earlier GTK3
  harness showed that the installed toolkit also initializes Xlib itself,
  so the proposed `startx` failure was not reproduced on this machine.

### GTK3 limitation

The production application intentionally refuses GTK3 with Lazarus below
4.99 (`LCLGTK3 is not production ready`). This guard is preserved.
The diagnostic harness on 4.8 is not evidence of production GTK3 support;
a full GTK3 application validation requires a supported Lazarus version.

The GTK3 theme/icon diagnostic exits with four failing groups: loose SVG
pixel selection, XDG theme pixel selection, converted WordSized PNG pixels,
and absolute-PNG resizing/pixels. Archive rejection, lifetime and legacy
fallback groups pass. The failures are recorded, not waived as successes
or fixed by weakening assertions. Their root cause has not been established
on a supported GTK3/Lazarus combination.

### Build and test notes

From the worktree root:

```sh
lcl=qt6 ./build.sh components
(
  cd src
  lazbuild --skip-dependencies --build-all --ws=qt6 \
    --build-mode=release doublecmd.lpi
)
lazbuild --skip-dependencies --build-all --ws=qt6 \
  tests/ui_theme_regression.lpi
lazbuild --skip-dependencies --build-all --ws=qt6 \
  tests/theme_icon_regression.lpi
```

Test executables are under `units/x86_64-linux-ui-theme-tests/qt6/` and
`units/x86_64-linux-theme-icon-tests/qt6/`. Each run requires an isolated
`--config-dir`; the theme test additionally requires `XDG_DATA_HOME` and
`XDG_DATA_DIRS` pointing to that directory's `xdg-user` and `xdg-system`
children. Use `QT_QPA_PLATFORM=offscreen` for headless Qt6 runs.
Repeat the theme executable with the same configuration root and
`--expect-theme=resized` to verify saved-theme persistence.

On this machine GTK units are in Lazarus's user-owned fallback directory.
GTK builds need the appropriate `--opt=-Fu...` paths for LCL, LazControls,
SynEdit and DateTimeCtrls under `$HOME/.lazarus/lib`. This is an environment
requirement, not a source-code workaround.

Native Wayland mouse/focus/tooltip behavior, visual quality on a real HiDPI
display beyond automated assertions, interactive theme switching/restarting
the full application, and Windows/macOS runtime behavior still require
those interactive or platform-specific checks.
